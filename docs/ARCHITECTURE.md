# SplitScreen.Me v3 site: architecture

Status: **normative**. This document is the single source of truth for the site. A change that deviates from it updates this file in the same commit, and says so in the pull request.

- Repo: `SplitScreen-Me/splitscreenme-hub`, orphan branch `v3.0.0-beta`.
- Replaces the Meteor hub (`splitscreenme-hub@master`) and the Docusaurus site (`splitscreenme-www`, to be archived). Both are reference only.
- Beta target: `https://v3.splitscreen.me` (noindex). The final domain is set by `SITE_URL`; nothing hardcodes a host.

## 0. Decisions at a glance

| Topic | Decision |
|---|---|
| App | One Next.js 15 App Router app: landing, hub, docs, accounts, backoffice, API |
| Rendering | Every HTML page is dynamic (nonce CSP). Hot data is cached in an in-process LRU and invalidated on write |
| DB | PostgreSQL 16, Drizzle ORM 0.45 with the postgres-js driver, `casing: 'snake_case'` |
| Ids | Legacy Meteor ids (17 chars) stay the primary keys of users, handlers, versions and comments. New ids use the same format |
| Auth | Small custom implementation: database sessions (Lucia-style), bcryptjs, an in-repo OAuth 2.0 / OIDC client on `fetch` and `node:crypto`. No auth framework |
| API | `/api/v3`, public and cookie-less, `Access-Control-Allow-Origin: *`, zod schemas, OpenAPI 3.1 generated by `@asteasolutions/zod-to-openapi`, self-hosted Swagger UI |
| Files | Packages live on a bind-mounted storage volume. nginx serves them through `X-Accel-Redirect` after the app has checked and counted |
| Docs | MDX files in `src/content/docs`, compiled at build by `@next/mdx`, one nav file drives sidebar, sitemap and prev/next |
| Search | Postgres `pg_trgm` + `unaccent` (catalogue), `tsvector` for handler text |
| Jobs | In-process timers started from `instrumentation.ts` (single instance) |
| Deploy | Image built locally, `docker save` / `docker load`, compose on the server: `db` (200 MB) + `web` (320 MB) on `127.0.0.1:3010`, nginx + certbot |

## 2. Data model (Drizzle)

`src/db/schema.ts` is shared (protocol in 10.4). The client is `drizzle({ client: postgres(DATABASE_URL, { max: 5, idle_timeout: 20, connect_timeout: 10 }), schema, casing: 'snake_case' })`, also `casing: 'snake_case'` in `drizzle.config.ts`. TypeScript keys are camelCase, SQL columns snake_case. All timestamps are `timestamptz`.

### 2.1 Custom SQL (hand-written migrations)

`drizzle/0000_extensions.sql` (custom, before the generated tables):

```sql
CREATE EXTENSION IF NOT EXISTS pg_trgm;
CREATE EXTENSION IF NOT EXISTS unaccent;
CREATE OR REPLACE FUNCTION immutable_unaccent(text) RETURNS text
  LANGUAGE sql IMMUTABLE PARALLEL SAFE STRICT
  AS $$ SELECT public.unaccent('public.unaccent'::regdictionary, $1) $$;
```

`drizzle/0002_audit_guard.sql` (custom, after the tables): `audit_log` is append-only.

```sql
CREATE OR REPLACE FUNCTION audit_log_guard() RETURNS trigger LANGUAGE plpgsql AS $$
BEGIN
  IF TG_OP = 'DELETE' AND current_setting('ssm.audit_purge', true) = 'on' THEN RETURN OLD; END IF;
  RAISE EXCEPTION 'audit_log is append-only';
END $$;
CREATE TRIGGER audit_log_append_only BEFORE UPDATE OR DELETE ON audit_log
  FOR EACH ROW EXECUTE FUNCTION audit_log_guard();
```

### 2.3 Rules around the schema

- **Listed handler** (the only thing the public ever sees), one predicate in `src/server/public/visibility.ts`: `deleted_at is null and is_public and approved_at is not null and current_version_id is not null`. In `src/server/public`, handler lists start from `listedSummaries(where)`, which always ANDs the predicate (never chain `.where()` on it). A game is public when it has at least one listed handler.
- **Primary handler of a game**: `games.featured_handler_id` if it is listed, otherwise the listed handler ordered by verified current version first, then `trend_score desc`, `download_count desc`, `created_at asc`.
- **Handler states** shown to authors: draft (no version, `is_public` forced false), private, awaiting approval (`is_public` and no `approved_at`), listed, plus the flag "current version unverified". A moderator hides a handler by revoking the approval; the owner cannot override it. A new upload keeps the handler listed but unverified, as today. Authors with `trusted_author` get `approved_at` set on creation.
- **Counters** (`download_count`, `star_count`, `comment_count`, `open_report_count`, version `download_count`) are updated by the application in the same transaction as the change (`set x = x + 1`). A daily job recomputes them from source rows and logs any drift. `trend_score` = sum of `handler_download_days.downloads` for `day >= current_date - 3`, recomputed every 15 minutes in one `UPDATE`.
- **Soft deletes**: users (anonymised), handlers, versions, comments. Every public query filters `deleted_at is null`. Hard deletes only happen through cascades of handler purges, which v3.0 does not offer.
- **Account deletion**: delete sessions, OAuth accounts, tokens and stars; set `username = 'deleted-' + id.slice(0, 6)`, `email`, `password_*` to null, `deleted_at = now()`; soft-delete the user's comments (body cleared). Public handlers stay, shown as "Deleted user". This is stated in the privacy policy.
- **Search** (catalogue, API `q`): split `immutable_unaccent(lower(q))` into at most 5 words; every word must match `games.name_search || ' ' || handlers.title_search || ' ' || lower(users.username)` with `LIKE '%word%'` (trigram indexes serve it). Order: exact game name, game name prefix, `greatest(similarity(name_search, q), similarity(title_search, q))`, then `trend_score`. If nothing matches, fall back to `games.name_search % q` (fuzzy). `search_tsv` serves admin search in descriptions.
- **Ids**: `newId()` in `src/lib/ids.ts` = 17 chars from Meteor's alphabet `23456789ABCDEFGHJKLMNPQRSTWXYZabcdefghijkmnopqrstuvwxyz`, `crypto.getRandomValues` with rejection sampling. It matches the app's `^[A-Za-z0-9]{1,64}$`.
- **Slugs**: `slugify(name)` (NFKD, strip accents, lower, `[^a-z0-9]+` to `-`, trim, max 80). Collision with another game: append `-<releaseYear>`, then `-<igdbId>`. Changing a slug inserts the old one into `game_slug_redirects` (308).

## 3. Mongo to Postgres migration

The importer reads the Meteor database `hubdb` (Mongo 4.0) and the GridFS bucket, and writes Postgres and the storage volume.
- Code: `scripts/import-mongo.ts`, with the mapping in `scripts/import/`.
- Runbook: `scripts/README.md`.

**Modes.**
- **`--reset`** (with `IMPORT_CONFIRM=ssm-v3`) is the **full replace** used for releases: `TRUNCATE ... RESTART IDENTITY CASCADE` of every table except `audit_log`. Sessions go too, so everyone logs in again.
- **Without `--reset`** it **upserts**, so a re-run is safe during the beta, while the old hub stays live.
  - Catalogue rows (games, handlers, versions, download days) are refreshed from Mongo, except what v3 owns, read from the audit log:
    - a handler with any `handler.*` or `version.*` entry (owner edit, publish/unpublish, approval or revocation, transfer, deletion, upload, verification), or whose owner is banned or deleted on v3, keeps every v3 column; only its download counter moves;
    - a version verified or unverified on v3 keeps that state; a version deleted on v3 stays deleted;
    - a game edited or refreshed on v3 is matched, not overwritten;
    - a newer version uploaded on v3 stays current, and Mongo's current version is not restored over a v3 deletion;
    - a Mongo package whose number a v3 upload already uses is left out (an already imported one keeps its number) and listed in the report, instead of aborting the phase on the unique index.
  - Download counters (`handlers`, `handler_versions`, `handler_download_days`) add Mongo's new downloads to those counted on v3: `count - imported_* + new Mongo value`, where `imported_*` is the Mongo value of the previous run.
  - Handlers and versions gone from Mongo (deleted on the old hub) and not created on v3 are soft-deleted, so a takedown there propagates. More than `max(25, 2 %)` of the source at once means a wrong source: nothing is deleted, the ids are listed and the run fails.
  - Account and community rows (users, OAuth, stars, comments, reports) are only inserted when missing, so changes made on v3 are kept (except a star removed on v3, which a re-run brings back while the user still has it on the old hub).
- **`--dry-run`** writes nothing.

**Transactions.** Each phase runs in its own transaction.

**Files.** The file export is incremental. `STORAGE_DIR/import/files-index.json` remembers the GridFS id, size, sha256 and manifest of each file. A file still on disk with the same GridFS id and size is skipped.

**Report.**
- It has counts, ids and checks. The checks verify that every source collection equals what was imported plus what was skipped, by reason, and that the Postgres rows match the plan. A failed check makes the exit code 1.
- An audit entry `system.import` follows.
- It never logs personal data. Drizzle's failed-query messages carry parameters, so the importer prints only the Postgres code and names.

**Phases**, in order (`--only` takes these names):
1. `users`;
2. `games`;
3. `handlers`;
4. `files` (GridFS export, no DB writes);
5. `versions`;
6. `stars`;
7. `comments`;
8. `downloads`;
9. `reports` (synthetic);
10. `counters` (stars, comments, open reports, trend), then `ANALYZE`.

The report goes to stdout and `STORAGE_DIR/import/last-report.json`. Text fields lose any NUL character, which Postgres rejects (2 legacy packages on 2026-10-12).

**Legacy password check, verified on the Meteor sources** (`accounts-password` `password_server.js`, `sha` `sha256.js`): Meteor stores `bcrypt(SHA256(password))` where SHA256 is the lower-case hex digest of the password encoded **code unit by code unit** (each UTF-16 unit as 1 to 3 bytes, so characters outside the BMP become CESU-8, not UTF-8). bcrypt sees the 64-char hex string.

```ts
// src/lib/auth/password.ts
export function meteorDigest(password: string): string {
  const bytes: number[] = [];
  for (let i = 0; i < password.length; i++) {
    const c = password.charCodeAt(i);
    if (c < 0x80) bytes.push(c);
    else if (c < 0x800) bytes.push(0xc0 | (c >> 6), 0x80 | (c & 63));
    else bytes.push(0xe0 | (c >> 12), 0x80 | ((c >> 6) & 63), 0x80 | (c & 63));
  }
  return createHash('sha256').update(Uint8Array.from(bytes)).digest('hex');
}
```

Test vectors (computed with Meteor's own `sha256.js`): `"password"` -> `5e884898da28047151d0e56f8dc6292773603d0d6aabbdd62a11ef721d1542d8`; `"Pässwörd"` -> `b9fdf96f902f18de9c513b0b05383d0f47a06890832799cc0af2f583df530f61` (same as UTF-8); `"pa😀ss"` -> `c7d5eed2694b19366906134fce32b38721c59d229fcbe53adeccd709e1044fb4` (differs from UTF-8).

On login: `meteor_sha256_bcrypt` -> `bcryptjs.compare(meteorDigest(pw), hash)`; on success rehash `bcryptjs.hash(pw, 11)` and set `password_algo = 'bcrypt'` in the same request. `bcrypt` -> `compare(pw, hash)`, rehash when the cost is below 11.

## 4. Authentication

### 4.1 Choice: small custom implementation (database sessions + in-repo OAuth client)

Rejected:

- **Auth.js v5** never left beta and is now maintained by the Better Auth team in maintenance mode. Its credentials provider discourages database sessions.
- **better-auth** would work, but three of our core needs become hooks around its internals: verifying a non-standard legacy hash and rehashing it, linking by verified email with pre-hijack protection, and legacy string ids. It also brings its own table layout (`account.password`, `verification`) and a plugin system we do not use, in a 320 MB container.

Chosen: the session model of the Lucia guide (now a reference implementation, not a library), `bcryptjs` for passwords, and for the OAuth 2.0 / OIDC exchanges a small client of our own in `src/lib/auth/oauth.ts` (provider endpoints and scopes, state, PKCE S256, code exchange with `client_secret_post`, Google ID token claims checked for issuer, audience and expiry, normalised profile with the provider's email-verified flag), with hashing and encoding on `node:crypto` (`src/lib/crypto.ts`). (Deviation from the first plan: Arctic and `@oslojs/crypto` were deprecated on npm on 2026-07-29, see section 11; the client does what Arctic did for these three providers.) About 600 lines in `src/lib/auth` and `src/server/auth`, all pure JS, every rule below written down and covered by tests. That is the audited part: any change to it is reviewed against this section.

### 4.2 Sessions (`src/lib/auth/session.ts`)

- Token: 20 random bytes, base32 lower case without padding (`randomBase32` in `src/lib/crypto.ts`). Stored id: hex `sha256(token)`. The token is never stored.
- Cookie: `__Host-ssm_session` in production (`ssm_session` when `SITE_URL` is http), `HttpOnly; Secure; SameSite=Lax; Path=/`, `Max-Age` 30 days. Rendering cannot set cookies, so the middleware re-sends the session cookie with a fresh `Max-Age` on page GETs; the database expiry (slid on validation) stays the authority.
- Validation: one query joining `users`; rejected if expired, user deleted or banned. Expiry slides to 30 days when less than 15 remain. `last_seen_at` written at most once an hour. Wrapped in React `cache()` per request: `getCurrentUser()`.
- New session on every login (no fixation); the session the browser held before is deleted. Logout deletes the row. Password change or reset, email change, ban, role change and account deletion delete all the user's sessions (except the current one for a password change or an email change made from the account page; an email change confirmed by link keeps the confirming browser's session).

### 4.3 Email and password

- Register: username (3..20, `^[A-Za-z0-9_-]+$`, not reserved: `admin`, `moderator`, `splitscreen`, `splitscreenme`, `nucleus`, `system`, `api`, `root`, `deleted-*`), email, password (8 chars min, 72 UTF-8 bytes max, bcrypt's limit; not equal to the username or email), terms checkbox. Username and email unique case-insensitively. Hash: `bcryptjs.hash(pw, 11)`.
- Login: email or username + password. When the user does not exist, still compare against a fixed dummy hash (constant timing). Legacy hashes per 3.1. Generic error message.
- `canPost(user)` (comments, handler creation) = not banned and (`email_verified_at` set or at least one OAuth account), as the Meteor hub did.
- Verification, reset and email change tokens: 32 random bytes, base64url, sha256 stored in `auth_tokens`, single use, 1 hour (reset) or 48 hours (verify). Links carry the token in the fragment (`/reset-password#token=...`); the page posts it with a Server Action. The reset page sends `Referrer-Policy: no-referrer`.
- Reset request always answers "If an account exists, we sent an email". A successful reset sets the password, marks the email verified (inbox proven), deletes all sessions and opens a new one. When the address was not proven before (4.4), the reset is a takeover by proof: the OAuth links and pending tokens go too.
- **SMTP optional**: when `SMTP_URL` is unset, verification and reset emails are disabled, the UI hides "Forgot password?" and says so on the account page; moderators can mark an email verified. That mark (`email_verified_by_moderator`) lets the account post but is not an inbox proof: the OAuth rules of 4.4 do not trust it. Never `rejectUnauthorized: false`: `smtps://` or STARTTLS with `requireTLS: true`.

### 4.4 OAuth (Discord, GitHub, Google)

- A provider is enabled only when both `<PROVIDER>_CLIENT_ID` and `<PROVIDER>_CLIENT_SECRET` exist. The login page lists enabled providers only. Facebook identities are imported but there is no Facebook login; those users sign in with another provider using the same verified email, or reset a password.
- Redirect URI: `${SITE_URL}/api/auth/oauth/<provider>/callback`. Register it on the existing provider apps (the hub's apps keep the same user ids).
- Start (`GET /api/auth/oauth/[provider]`): rate limited; `state = generateState()`, `codeVerifier` for Google and Discord; one cookie `__Host-ssm_oauth` (`HttpOnly; Secure; SameSite=Lax; Path=/; Max-Age=600`) holding `{ provider, state, codeVerifier, next, intent }`. `next` (`safeNextPath` in `src/lib/urls.ts`) must start with `/`, contain no ASCII control character and no backslash (URL parsers drop tabs and newlines, so `/\t/evil.com` would become `//evil.com`), and resolve to the site's own origin; otherwise the fallback is used. `intent=link` requires a session.
- Scopes and profile: Discord `identify email`, `GET https://discord.com/api/users/@me` (`id`, `username`, `email`, `verified`). GitHub `read:user user:email`, `GET /user` and `GET /user/emails` (primary and verified address). Google `openid email`, claims of the ID token (`sub`, `email`, `email_verified`).
- Callback: compare `state` with the cookie (constant time), delete the cookie, exchange the code, then resolve the user:
  1. `oauth_accounts(provider, providerUserId)` exists: that user (refused if banned or deleted).
  2. `intent=link`: attach to the session user, unless the identity belongs to someone else (error). An account whose address is not confirmed cannot gain a sign-in method (`link_requires_verified_email`), unless the provider's verified address is that very address (then it also becomes verified).
  3. The provider says the email is verified and a user has that email. An address is **proven** when `email_verified_at` comes from an inbox proof: a confirmation link, a reset, a provider's verified address, or the legacy hub, not a moderator's mark (`rules.ts` `emailProven`).
     - Proven: link and log in.
     - Not proven (unconfirmed, or only marked by a moderator): whoever registered the address may not own it (account pre-hijacking), and anything they attached would survive a plain link. **Takeover by proof** (`src/server/auth/takeover.ts`): delete every OAuth link, session and pending token of the account, clear the password, mark the email verified, audit `auth.email_takeover`, then link the prover's identity and log in.
     - The holder is banned: refused if the address is proven; otherwise the banned account loses the address (`auth.email_released`) and rule 4 creates the prover's account.
  4. Otherwise create a user: username from the provider (sanitised, de-duplicated), email only if verified (and not used by another account), `email_verified_at = now()` then.
- A verified claimant takes an address held without proof, which then no longer blocks the real owner: an email change confirmed by link releases it from the other account (`auth.email_released`), and with SMTP the change request is accepted for such an address (the link decides). Registration (no proof) and the change without SMTP still refuse any address in use; the real owner then uses a reset or a provider sign-in, which take the account over.
- Unlinking is allowed only if another way to log in remains (password or another provider).

### 4.5 CSRF and rate limits

- Server Actions: Next.js rejects a request whose `Origin` differs from `X-Forwarded-Host`/`Host`; nginx forwards both unchanged, so no `allowedOrigins` is needed (it would be frozen at build anyway, see 6.4).
- Route handlers that read the session and change state (`/api/me/**` POST, link/unlink): `assertSameOrigin(req)` requires `Origin` equal to the `SITE_URL` origin, else 403. Every state change is a POST. Cookies are `SameSite=Lax`.
- `/api/v3/**` never reads cookies, so cross-origin calls cannot act as a user.
- Rate limits: table in 6.5.

### 5.2 Conventions (`src/lib/api/http.ts`)

- Every route is wrapped by `withApi(handler, { rateLimit })` and exports `OPTIONS = preflight`.
- Headers on every response: `Access-Control-Allow-Origin: *`, `Access-Control-Allow-Methods: GET, HEAD, POST, OPTIONS`, `Access-Control-Allow-Headers: Content-Type, If-None-Match`, `Access-Control-Expose-Headers: ETag, Retry-After, Content-Disposition`, `Access-Control-Max-Age: 86400`, `Cross-Origin-Resource-Policy: cross-origin`, `X-Content-Type-Options: nosniff`. Never `Access-Control-Allow-Credentials`.
- Reads: `ETag` (weak, hash of the payload or of the newest `updated_at`), `304` on `If-None-Match`, `Cache-Control: public, max-age=60, stale-while-revalidate=300` (catalogue: `max-age=300, stale-while-revalidate=3600`).
- Errors: `{ error: { code, message, issues? } }` with `code` in `bad_request` (400, zod issues), `not_found` (404), `rate_limited` (429 + `Retry-After`), `payload_too_large` (413), `internal` (500, no stack).
- Ids validated with `^[A-Za-z0-9]{1,64}$` before any query.

### 5.5 Download

1. Validate, rate limit (`download` bucket), load the listed handler and the requested non-deleted version, 404 otherwise.
2. Count only for `GET` with `count` not `false`, no `Range` other than `bytes=0-`, and a user agent not matching `/bot|crawler|spider|preview|curl\/|wget\//i`: in one transaction, `INSERT INTO download_dedup(key) ... ON CONFLICT DO NOTHING RETURNING key` with two keys: `HMAC-SHA256(APP_SECRET, ip|handlerId|version|utcDay)` (version level) and `HMAC-SHA256(APP_SECRET, ip|handlerId|handler|utcDay)` (handler level). A new version key adds `handler_versions.download_count + 1`; a new handler key adds `handlers.download_count + 1` and upserts `handler_download_days (handler, today) + 1`. Asking for every version therefore counts each version once but the handler (its total, its days, so its trend and its primary rank) once per address and day. A repeated download is served but not counted.
3. Respond with `Content-Type: application/zip`, `Content-Disposition: attachment; filename="handler-<id>-v<n>.nc"`, `ETag: "<sha256>"`, `Repr-Digest: sha-256=:<base64>:`, `Cache-Control: private, no-cache`. With `STORAGE_ACCEL_PREFIX` set: empty body plus `X-Accel-Redirect: <prefix><storageKey>`, nginx streams the file (`internal` location). Without it (local dev): stream from Node (`fs.createReadStream` -> `Readable.toWeb`) with `Content-Length`.

The app should check the sha256 after downloading (note for the app).

As built: the package must exist on disk (`stat`), otherwise `404` and an error log, nothing counted. `If-None-Match` equal to the sha256 ETag answers `304` (not counted). The counting runs in one transaction with the dedup insert and keeps `handlers.updated_at` (a download is not an edit); a counting failure is logged and the file is still served. Without `STORAGE_ACCEL_PREFIX`, Node also serves a single `Range` (`206`). Behind `X-Accel-Redirect`, nginx only passes a few upstream headers (`Content-Type`, `Content-Disposition`, `Cache-Control`...): `Repr-Digest`, the sha256 `ETag`, `X-Robots-Tag` and the CORS headers other than the one the internal location adds are dropped, and nginx sets its own `ETag`. The sha256 in the JSON is the reference; nginx may add `add_header Repr-Digest $upstream_http_repr_digest always;` to the internal location.

### 5.6 Reports

Rate limited (6.5), body validated, then: one open report per `(target, reporterHash)` per 24 h (a duplicate returns 202 without inserting); `open_report_count + 1`; audit `report.create`. `reporterId` is never set by the API (it does not read cookies); the site's report form posts to the same endpoint.

As built (`src/server/reports.ts`): the body is read as JSON whatever its `Content-Type` (a browser can post without a preflight; no cookie is read, so no CSRF), cut at 4096 bytes while streaming (`413`); a `version` must be a non-deleted version of the handler (`400` with an issue on `version`); control characters are stripped from `message`; the duplicate check runs under a transaction-scoped advisory lock on `(handler, reporterHash)`; `updated_at` of the handler is kept.

## 6. Security

### 6.1 Private handlers are never exposed

- Public pages, the API, the sitemap, OG images and search import data **only** from `src/server/public/**`, which applies the listed predicate (2.3). ESLint `no-restricted-imports` forbids `@/db/schema` and `@/server/private/**` in `src/app/(site)/hub/**`, `src/app/api/v3/**`, `src/app/sitemap.ts`, `src/app/robots.ts` and the OG routes.
- Owner and moderator reads live in `src/server/private/**`, each function takes the user and checks `can()`.
- Non-listed resources answer 404 everywhere. Old version downloads are allowed only for listed handlers.
- Tests (a and b): fixtures with a private, an unapproved, a deleted, a version-less and a listed handler; every public route, the sitemap and the API must show only the listed one.

### 6.2 Roles and permissions (`can(user, action, resource)` in `src/lib/auth/permissions.ts`)

| Action | anonymous | user | owner | moderator | admin |
|---|---|---|---|---|---|
| read listed content, download, report | yes | yes | yes | yes | yes |
| star | | yes | yes | yes | yes |
| comment (needs `canPost`) | | yes | yes | yes | yes |
| delete own comment | | yes | | yes | yes |
| create handler (needs `canPost`) | | yes | | yes | yes |
| edit handler, upload version, public/private, soft-delete | | | yes | yes | yes |
| read private handlers, scripts, manifests | | | own | yes | yes |
| approve or revoke a handler, verify a version, hide comments, resolve reports, edit games, mark email verified, trusted author flag | | | | yes | yes |
| ban, change roles, transfer ownership, restore deleted, delete accounts, view audit log | | | | | yes |

Admins cannot demote or ban themselves; the last admin cannot be demoted; an admin must be demoted before being banned or deleted. Moderators can also restore a comment they hid (not one its author deleted) and soft-delete a version (`version.verify` permission; the newest remaining version becomes current, or the handler goes back to draft). In the backoffice, email addresses are shown to admins only (moderators see confirmed or not); searching users by exact email is admin-only. A username can change once every 30 days (case-only changes are free). Banned users cannot log in (their sessions are deleted); a ban can also unpublish all their handlers (checkbox, audited). Old `admin` maps to `admin`; nobody becomes moderator automatically.

### 6.3 Upload validation (`src/server/packages/`)

1. Session, `can('version.upload')`, `canPost`, rate limit, one upload processed at a time (in-process semaphore, others wait up to 30 s then 503).
2. nginx accepts 32 MB on `/api/me/` only. The route streams the multipart body with busboy straight to `STORAGE_DIR/uploads/<uuid>` (no buffering in memory), counting bytes and hashing; abort beyond **31 457 280 bytes** (30 MiB, the current limit). Fields: `releaseNotes` (2..2000 chars), `package` (`.nc` or `.zip`).
3. Magic bytes `PK\x03\x04`. `yauzl.open(path, { lazyEntries: true, validateEntrySizes: true, strictFileNames: true })`.
4. Entries: at most 5000; reject absolute paths, drive letters, `..` segments, backslashes, NUL or control characters, names over 260 chars, case-insensitive duplicates, symlinks (`(externalFileAttributes >>> 16) & 0o170000 === 0o120000`), encrypted entries (general purpose bit 0). **Zip bomb**: sum of declared uncompressed sizes ≤ 250 MiB, any entry over 1 MiB with a ratio above 100:1 rejected, and the real decompressed byte count is enforced while streaming (declared sizes are not trusted).
5. `handler.js` at the root (case-insensitive, renamed to `handler.js`), ≤ 2 MiB, valid UTF-8 (`TextDecoder('utf-8', { fatal: true })`, BOM stripped), must assign `Game.GameName` or `Game.ExecutableName` (the app refuses packages without them).
6. **Stamp** (the app's update check depends on it): remove lines matching `^\s*Hub\.(Handler\.(Id|Version)|Maintainer\.(Id|Name))\s*=.*$` (multiline), then prepend, keeping the file's line endings:
   ```js
   Hub.Handler.Version = <n>; // Released at <SITE_URL> on <ISO date>.
   Hub.Handler.Id = "<handlerId>";
   Hub.Maintainer.Name = <JSON.stringify(owner username)>;
   Hub.Maintainer.Id = "<ownerId>";
   ```
   `<n>` = `greatest(current_version, max(version)) + 1` (legacy handlers can have versions above `current_version`, and the number is unique per handler), computed under the upload mutex and checked again under `SELECT ... FOR UPDATE` on the handler in the insert transaction. The maintainer is the handler owner (Meteor used the uploader).
7. Rebuild the zip with yazl (deflate), streaming each original entry through the byte counters, `handler.js` replaced; 120 s timeout. Final sha256 and size; `manifest` = `[{ path, size }]`; rename into `packages/<handlerId>/<versionId>.nc`.
8. One transaction: insert the version (unverified), set `current_version_id`, `current_version`, `updated_at`; audit `version.upload` with the manifest summary (count of `.exe`/`.dll`/`.bat`/`.ps1` entries, flagged in the admin view). Any failure deletes the temp and final files. Temp files older than 1 hour are purged by a job.
9. No antivirus is available on the server: verification by a moderator stays the safety net, and the site says "unverified" clearly.

### 6.4 Headers and CSP

`src/middleware.ts` (`runtime: 'nodejs'`; with a `src/` directory Next requires it there, as `src/instrumentation.ts` and `src/mdx-components.tsx`) runs on pages only. Matcher excludes `api/v3`, `api/me`, `api/auth`, `_next/static`, `_next/image`, `api-docs`, `doc/img`, `favicon.ico`, `icon.svg`, `icons`, `robots.txt`, `sitemap.xml` (excluding `/api/me` also keeps Next from buffering upload bodies). It generates a 16-byte base64 nonce, forwards it as `x-nonce` and in the request CSP so Next applies it to its scripts, and sets:

```
Content-Security-Policy: default-src 'self'; script-src 'self' 'nonce-<n>' 'strict-dynamic'; style-src 'self' 'unsafe-inline';
  img-src 'self' data: blob: https://images.igdb.com https://cdn.akamai.steamstatic.com https://shared.akamai.steamstatic.com https://cdn.cloudflare.steamstatic.com;
  font-src 'self'; connect-src 'self'; frame-src https://www.youtube-nocookie.com; frame-ancestors 'none';
  base-uri 'self'; form-action 'self'; object-src 'none'; manifest-src 'self'; upgrade-insecure-requests
```

(`'unsafe-eval'` added in development only.) Static headers in `next.config.ts` for every route: `Strict-Transport-Security: max-age=63072000` (no `includeSubDomains`, no preload: other subdomains are not ours to decide), `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`, `X-Frame-Options: DENY`, `Cross-Origin-Opener-Policy: same-origin`, `Cross-Origin-Resource-Policy: same-origin` on every path except `/api/v3/**`, whose `cross-origin` comes from `withApi` (config headers win over route handler headers in Next, so the API is excluded from that rule rather than overriding it), `Permissions-Policy: camera=(), microphone=(), geolocation=(), payment=(), usb=(), browsing-topics=()`. `poweredByHeader: false`.

**Gotcha:** a standalone build freezes `next.config.ts` (headers, redirects, `serverActions`) at build time, and Edge middleware inlines `process.env` at build too. Anything that depends on the environment (`NOINDEX`, `SITE_URL`, `BETA`) is read at runtime (a static `export const metadata` is evaluated at build too: anything using `SITE_URL`, such as `buildMetadata` with a canonical, goes in `generateMetadata`): in the Node.js middleware (`X-Robots-Tag: noindex, nofollow` on pages), in `withApi` (same header on API responses) and in server components (metadata, banner). The image is built once and runs with any `.env`.

User content: handler descriptions render with `react-markdown` + `remark-gfm`, `skipHtml`, the default URL filter, links `rel="nofollow ugc noopener noreferrer"`, images turned into links (no third-party image loads), headings shifted down two levels. Comments are plain text with line breaks and autolinked http(s) URLs. JSON-LD goes through `<JsonLd>` (the only allowed `dangerouslySetInnerHTML`, `<` escaped as `\u003c`).

| `verify-resend` | 3 / h per user |
| `oauth-start` | 20 / min per IP |

### 6.7 TLS and secrets

- No TLS bypass anywhere: never `NODE_TLS_REJECT_UNAUTHORIZED`, `rejectUnauthorized: false`, `checkServerIdentity` overrides or `http://` to third parties. `scripts/check-security.mjs` (run by `npm run lint`) fails on these patterns and on `dangerouslySetInnerHTML` outside `JsonLd.tsx`.
- Secrets only in the environment, validated by `src/lib/env.ts` (zod) at first use; never logged. `.env*` (except `.env.example`), dumps, `.data/`, `storage/` are gitignored.
- Logs (`src/lib/log.ts`, JSON lines to stdout, no dependency): request id, route, status, duration; never tokens, cookies, emails, passwords or raw IPs.
- Errors are logged without data: Drizzle's `DrizzleQueryError` message ends with `params: <values>` (emails, usernames, hashes, whole scripts) and Postgres' `detail` quotes row values. `log.ts` keeps the message up to `params:`, the stack frames, and of the cause only `code`, `constraint_name`, `table_name`, `column_name`. Next.js prints uncaught Server Action, route and page errors with `console.error` (`util.inspect` shows an error's own `params` and its cause): `instrumentation.ts` installs `scrubConsoleErrors()`, which prints such errors sanitised.

### 8.1 MDX approach

- `@next/mdx` compiles `.mdx` at build (webpack), so no MDX compiler at runtime. Plugins in `src/content/mdx-options.ts` (imported by `next.config.ts`): `remark-gfm`, `rehype-slug`, `rehype-autolink-headings` (`behavior: 'wrap'`), `@shikijs/rehype` (theme `github-dark-default`, build time only).
- Content: `src/content/docs/<path>.mdx`, each exports `export const meta = { title, description, updated: 'YYYY-MM-DD' }`.

It drives the sidebar, prev/next, breadcrumbs and the sitemap (no `generateStaticParams`: pages render per request because of the CSP nonce, MDX is already compiled). A test checks every nav entry has a file and every file is in the nav.
- Route `src/app/(site)/doc/[[...slug]]/page.tsx` imports the file with `await import(\`@/content/docs/${file}.mdx\`)`; unknown slugs 404.
- `src/mdx-components.tsx` (required by `@next/mdx`; inside `src/` because the app lives there) maps headings, links (external `rel="noopener"`), tables, code, images (`public/doc/img/`) to Bezel styles and exposes `<Callout type="note|tip|warning">`, `<Steps>`/`<Step>`, `<Kbd>`, `<Figure>`, `<YouTube id>` (click to load, `youtube-nocookie.com`), `<GameLink slug>`. "On this page" is a small client component reading `article h2[id], h3[id]`.
- Docusaurus specifics: `:::note` becomes `<Callout>`, `TOCInline` is dropped, images move from `splitscreenme-www/static/img` to `public/doc/img`.
- As built (deviations from the lines above in italics):
  - Components live in `src/components/docs/` (`mdx.tsx`, `YouTube.tsx`), plus `<Card>`/`<CardGrid>` (overview cards) and `<SiteUrl path>` (an absolute URL from `SITE_URL`, for the API page). `<GameLink slug>` looks the game up (cached) and falls back to a hub search link, so docs never link to a 404. Callout types: `note`, `tip`, `warning`, `danger`. The body of a page has no `#` heading: the page renders `meta.title` as the h1 (a test enforces it).
  - *Headings are read on the server*: `src/components/docs/doc-tree.ts` calls the compiled MDX function with pass-through components and walks the element tree, which gives "On this page" (rendered without JavaScript; a client component only highlights the section in view) and the text of the search index.

  - `src/content/docs/links.test.ts` checks every internal link and anchor of the docs, the legacy redirects, the meta of every page, and the 30 legacy FAQ anchors.

### 9.2 Dockerfile

```dockerfile
# syntax=docker/dockerfile:1.7
FROM node:24.21.0-alpine3.24 AS deps
WORKDIR /app
COPY package.json package-lock.json ./
RUN npm ci

FROM node:24.21.0-alpine3.24 AS build
WORKDIR /app
ENV NEXT_TELEMETRY_DISABLED=1 SKIP_ENV_VALIDATION=1
COPY --from=deps /app/node_modules ./node_modules
COPY . .
RUN npm run build \
 && node scripts/build-scripts.mjs \
 && rm -rf .next/standalone/node_modules/sharp .next/standalone/node_modules/@img \
 && node scripts/check-no-native.mjs .next/standalone dist

FROM node:24.21.0-alpine3.24 AS runtime
WORKDIR /app
ENV NODE_ENV=production NEXT_TELEMETRY_DISABLED=1 PORT=3000 HOSTNAME=0.0.0.0
COPY --from=build --chown=1001:33 /app/.next/standalone ./
COPY --from=build --chown=1001:33 /app/.next/static ./.next/static
COPY --from=build --chown=1001:33 /app/public ./public
COPY --from=build --chown=1001:33 /app/drizzle ./drizzle
COPY --from=build --chown=1001:33 /app/dist ./dist
USER 1001:33
EXPOSE 3000
HEALTHCHECK --interval=30s --timeout=5s --start-period=30s CMD wget -qO- http://127.0.0.1:3000/api/v3/health || exit 1
CMD ["sh", "-c", "umask 027 && node dist/migrate.mjs && exec node server.js"]
```

- `next.config.ts`: `output: 'standalone'`, `images: { unoptimized: true }`, `poweredByHeader: false`, `reactStrictMode: true`, `cacheMaxMemorySize: 0` (we cache in our own LRU), `experimental.serverActions.bodySizeLimit: '1mb'`, the static headers of 6.4, the docs redirects of 8.2, `withMDX`. Nothing environment-dependent (6.4).
- `scripts/build-scripts.mjs` bundles `scripts/migrate.ts` (drizzle-orm `migrate()` on `./drizzle`) and `scripts/import-mongo.ts` with esbuild into `dist/*.mjs` (`platform: node`, `format: esm`, externals: `kerberos`, `snappy`, `@mongodb-js/zstd`, `mongodb-client-encryption`, `gcp-metadata`, `socks`, `@aws-sdk/credential-providers`).
- `SKIP_ENV_VALIDATION=1` (build stage only) makes `env()` fill missing required values with placeholders instead of throwing, uncached. It is never set at runtime. A local `npm run build` stays strict, so code that reads the environment at build time (a static `metadata` export with a canonical, for example) fails there first.
- `scripts/check-no-native.mjs` fails the build if any `*.node` file or `binding.gyp` is left: runtime dependencies are pure JS (bcryptjs, no sharp, no argon2).
- Uid 1001, gid 33 (`www-data` on the host): with `umask 027`, nginx can read the package files the app writes.
- Every DB-backed route must be dynamic: the root layout reads `headers()` (nonce), and metadata routes (`sitemap.ts`, `robots.ts`) and route handlers that query declare `export const dynamic = 'force-dynamic'`. No `generateStaticParams` on DB-backed routes. Otherwise `next build` tries to reach Postgres.

### 9.3 Production compose (`deploy/docker-compose.prod.yml` -> `/root/v3/docker-compose.yml`)

The file in the repo is the reference; what matters on a small shared server:

- `db`: `postgres:16.15-alpine3.24`, `mem_limit: 200m`, `shm_size: 64m`, tuned small (`shared_buffers=48MB`, `max_connections=20`, `work_mem=2MB`, `effective_cache_size=96MB`, no parallel workers, `jit=off`, `log_min_duration_statement=500`), healthcheck `pg_isready`.   - `mem_limit: 320m` with `memswap_limit: 320m` (no swap: the host is already swapping) and `NODE_OPTIONS=--max-old-space-size=192 --max-semi-space-size=8`, so the V8 heap leaves about 100 MB for code, Buffers (30 MiB upload streams, zlib) and the WASM heaps of next/og (resvg, yoga). A heap at 256 MB in a 320 MB cgroup got the container SIGKILLed before V8 collected garbage.

The app's postgres-js pool is 5 connections; the importer uses 2. Before going live, check peak RSS with an upload and OG rendering running together (`docker stats`).

### 9.5 nginx (`deploy/nginx/v3.splitscreen.me.conf`)

The file in the repo is the reference:

- port 80: ACME webroot, otherwise 301 to https;
- port 443: certificates from certbot, `client_max_body_size 1m` (32m and a 180 s timeout on `/api/me/`, the uploads), gzip for JSON, JS, CSS, XML and SVG, `X-Real-IP`/`X-Forwarded-*` headers to `127.0.0.1:3010`;
- `/_storage/packages/`: `internal` alias of the storage volume, for `X-Accel-Redirect` downloads (5.5);
- `/releases/`: the app builds of the download page (8.3), static files from `/srv/ssm-v3/releases` (root-owned, world-readable, outside the app's storage), `try_files $uri =404` (no listing), `application/zip`, `expires 1d`, `X-Robots-Tag: noindex`, at most 4 concurrent downloads per IP (`limit_conn_zone ssmv3_files`, 429);
- HSTS (`max-age=63072000`, no `includeSubDomains`) is set by nginx, which hides the app's copy, so 429s and `X-Accel-Redirect` files carry it too;
- per-IP rate limits (6.5): `limit_req_zone` and `map` sit at the top of the file, in the `http` context shared with the other vhosts, so their names are prefixed `ssmv3_`. `ssmv3_pages` (20 r/s, burst 80) covers everything but `/_next/static/`, `ssmv3_search` (2 r/s, burst 20) only requests with a non-empty `q`, `ssmv3_og` (1 r/s, burst 20) the `opengraph-image` routes; `limit_req_status 429`.

### 9.7 Running the importer on the server

Runs next to the live Mongo, so personal data never leaves the server. Prefer a quiet hour, stop `web` to free memory.

```sh
cd /root/v3
# MONGO_URL copied from the hub container without printing it (host "mongodb" resolves on hub_default)
umask 077
docker inspect hub-hub-1 --format '{{range .Config.Env}}{{println .}}{{end}}' | grep -E '^MONGO_URL=' > .env.import
printf 'MONGO_DB=hubdb\nIMPORT_CONFIRM=ssm-v3\n' >> .env.import
# IGDB credentials: add IGDB_CLIENT_ID / IGDB_CLIENT_SECRET to .env (from the hub settings, without echoing them)
docker compose stop web
docker compose --profile tools run --rm importer --reset --igdb
docker compose start web
```

Flags: `--reset` (required to truncate, with `IMPORT_CONFIRM`), `--igdb`, `--skip-files`, `--only <phase,...>`, `--dry-run` (reads and validates, writes nothing). The importer opens Mongo read-only queries only, streams GridFS one file at a time, and prints the count report.

A container cannot reach the host's `127.0.0.1:27017`, so the importer joins `hub_default`, where the same mongod is `mongodb:27017`. `scripts/README.md` has the equivalent `docker run` command (`--network ssm-v3_default --network hub_default`), detached and niced from inside the container, which is the form `docs/DEPLOY.md` uses, and the procedure at release time.

### 10.2 Cache (`src/server/cache.ts`)

`cached(key, ttl, load, tags)` keeps hot public data in an in-process LRU (2 000 entries); `invalidate(...tags)` drops the entries carrying a tag after a write commits. Concurrent misses share one load; a load that an invalidation of one of its tags overtook returns its value but does not store it (per load, not a global generation, so unrelated writes never discard a slow load).

Bounded by construction, because keys come from URLs:
- callers validate input before any lookup (`getGameBySlug`: `^[a-z0-9-]{1,80}$`; `getHandler`: `isValidId`), and keys over 256 characters are never cached;
- the tag index only holds keys that are in the store: the LRU's `dispose` (eviction, expiry with `ttlAutopurge`, delete, replacement) removes a key from its tags and drops empty tags;
- misses (`null` or `undefined`, such as an unknown slug) go to a separate untagged LRU (500 entries, 30 s at most), cleared by any invalidation, so probing random URLs neither grows memory nor pushes real entries out.

Writes invalidate narrowly: a star toggle invalidates only `handler:<id>` and `game:<slug>` (catalogue star counts catch up on their 5-minute TTL), so a signed-in user cannot flush the whole cache.

### 10.3 Schema changes

- Edit `src/db/schema.ts` (new tables at the end, a trailing comment on a new column saying why), then `npm run db:generate -- --name <purpose>` and review the generated SQL. Custom SQL (extension, trigger, function, backfill) goes in a migration of its own (`drizzle-kit generate --custom`) or after the generated statements, separated by `--> statement-breakpoint`.
- Never edit a migration that has been deployed; add a new one.
- `npm run db:migrate` applies `drizzle/` locally; the container applies it at start (9.6).

### 10.4 Commits

English messages, logical commits. Never commit secrets, `.env` files, dumps or personal data (emails, hashes, names from the production data): they are gitignored, and test fixtures are synthetic.
